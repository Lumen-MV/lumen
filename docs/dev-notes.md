# Lumen — ghi chú kỹ thuật (dev notes)

Private Netflix-style streaming web app (Vietnamese UI) for a small friend group. Next.js 15 (App Router) + SQLite (Drizzle) + the approved static mockup's CSS ported 1:1 (`src/styles/*.css`, same class names).

## Dev (Windows)

```bash
cp .env.example .env.local        # fill SESSION_SECRET (32+ chars), ADMIN_USERNAME, ADMIN_PASSWORD, API keys
npm install
LUMEN_SCENARIOS=1 npm run dev        # http://localhost:3000 — migrates SQLite (./data) and seeds the admin on boot
npm run invite -- --note "Bảo"   # prints a one-time invite URL (7 days); --days 3|14, --multi
npm run seed -- --reset-password  # reset the admin password back to ADMIN_PASSWORD
```

- `better-sqlite3` on Windows: the pinned 13.x has no prebuilt binary for Node 22.23 (ABI 127), so `npm install` compiles it with `node-gyp` — install the Visual Studio Build Tools ("Desktop development with C++") once, or use a Node version the package ships prebuilds for. The Docker image always compiles it from source (Alpine), so the VM is unaffected.

- `npm run typecheck` · `npm run lint` · `npm test` (vitest) · `npm run build`
- `npm run qa:phase2` — Phase 2 contract + UX + extra Playwright scripts against a running `LUMEN_SCENARIOS=1 npm run dev` (Phase 1: `node tests/qa-api-contract-phase1.mjs`, `node tests/qa-ux-phase1-playwright.mjs`; geometry/pixel diffs: `tests/qa-layout-geometry-phase2.mjs --mock <dir>`, `tests/qa-pixel-diff.mjs`)
- `npm run qa:phase3` — Phase 3 sources / cloud jobs / resolve contract + UX scripts, then the `-extra` contract / picker scripts (ranking + 4K semantics, packs, title_sources, app queue, cancel semantics, request throttle, picker focus / a11y / outage behaviour). Real Torrentio + TorBox `checkcached` / `requestdl` on a cached title; cloud jobs run against the dev fake TorBox via the `cloud-sim=<spec>` scenario flag or the `cloud-jobs` seed fixture, so no real download is ever started; the resolved CDN link is probed once server-side with a 1 MB Range request. `GET /api/health` reports `torbox.calls` for the budget check.
- `npm run qa:phase4` — Phase 4 player / progress / My List contract + UX scripts. Every stream is the LOCAL ffmpeg sample (scenario `play-sample[=ac3|mkv]`; generated once into `qa/sample/` by `/api/dev/sample.mp4`), so the suite never touches TorBox: resolve → manifest (`direct`) and the stream proxy (`stream-mode=proxy` scenario override), Range 200/206/416/HEAD, link-expired relink ×2 (`link-expired[=fail]`), no-audio (AC3 track Chromium skips), codec error (`playback-fail` → MPEG-4/AC3 MKV), stall (held media request), offline, 5-viewer limit (`viewers` fixture), progress heartbeat / beacon / resume, series hero states, My List flows. The only real TorBox playback is the manual ≤ 20 s smoke `node tests/qa-smoke-real-torbox-phase4.mjs`.
- `npm run qa:phase6` — Phase 6 settings / admin / Stremio contract + UX scripts (`tests/qa-api-contract-phase6.mjs`: profile / password / device token lifecycle, the temp-password gate, every `/stremio/{token}/*` resource on the local sample incl. the proxy-mode `file` route and the per-token rate limits, admin stats / users / actions / invites / queue / activity + CSV, role scoping; `tests/qa-ux-phase6-playwright.mjs`: all 5 settings sections, every admin tab / dialog / ⋯ menu / filter, keyboard, 390 px tables, member 403, 0 console errors) followed by the `-extra` pair (`tests/qa-api-contract-phase6-extra.mjs`: settings defaults + validation, prefs honoured by sources / Stremio stream order / subtitle search, temp-password flow, lock → sessions + jobs + Stremio die, delete cascade verified in SQLite, invite validation, live cloud-sim queue, CSV secret scan + formula escape, KPIs vs DB, health shapes; `tests/qa-ux-phase6-extra.mjs`: keyboard-only dialogs with focus return, radio-group segs, "Gửi lại link", temp-password login + gate, 390 px clipping / tab strips, console sweep). Data = the `admin-data` fixture (members, sessions, invites, fake-TorBox jobs, activity) — TorBox ≤ 1 call in the main contract (plan lookup, memoised 6 h) and ≤ 2 in the extra one (one real `/api/sources` on Spider-Man; `QA_SKIP_REAL=1` skips it), no provider calls. `bash tests/qa-docker-stack-phase6.sh` (manual, needs Docker) builds the image, proves uid 1000 + bind-mount ownership, the one-off migration, the Caddy stack headers / limits / log redaction, `backup.sh` and the SIGTERM WAL checkpoint.
- `npm run qa:phase5` — Phase 5 subtitles contract + UX scripts (+ the `-extra` contract / UX scripts: auto-select matrix, quota bookkeeping, 600-cue job, kie-down → "Thử lại" resume, daily-limit semantics, cross-user job sharing, crafted cue markup / overlaps vs Chromium's native `<track>`, popover hotkeys / outside click), run through `tests/qa-run-sequence.mjs` so a failing script never skips the next one. The player's Âm thanh | Phụ đề popover (7 mockup states), band, offset / size prefs, `C` cycling and the AI-translate flow run against the LOCAL sample with the subtitle sim (`subs-sim=<popover state>` scenario → deterministic `subtitle_cache` rows + a fake translator; `os-quota-zero` / `kie-down` combine with it; the sample stream always runs in sim mode; the `subs-row` fixture adds a ready row with given cues). The contract script ends with ONE real-provider section (1 OpenSubtitles search + 1 download, 2 SubDL searches + 1 download, 1 Kie job on the 6-cue fixture ≈ 4 ₫) — skip it with `QA_SKIP_REAL=1` to protect the 20/day OpenSubtitles quota. Start the dev server with `LUMEN_SWEEPER=0` for the strict "TorBox untouched" assertion (otherwise the background sweeper's calls are only noted). Embedded (MKV) subtitle extraction is unit-tested against `qa/sample/sample-subs.mkv` (ffmpeg-generated) only, never against a TorBox file.
- Subtitles (Phase 5): `OPENSUBTITLES_API_KEY/USER/PASS`, `SUBDL_API_KEY`, `TRANSLATOR=kie|deepseek|claude` + `KIE_API_KEY` (or `DEEPSEEK_API_KEY` / `ANTHROPIC_API_KEY`). Search order embedded → OpenSubtitles → SubDL → AI; every fetched file is converted once to `DATA_DIR/subs/<id>.vtt`; translation jobs persist per batch in `DATA_DIR/jobs/<id>.json` and resume after a restart; limits 1 running job per user and 5 per day; the OS quota (`settings.os_quota_*`) and the month's AI spend (`settings.ai_month_cost_vnd`) are bookkept for the Phase 6 settings page.
- `STREAM_MODE=direct|proxy` (default `direct`): `direct` hands the TorBox CDN URL to `<video>` straight from `/api/play/manifest` JSON (VM egress ≈ 0, but the URL embeds the account API key → rotate it at torbox.app if a member leaves); `proxy` serves `/api/play/stream/[streamId]` and pipes the CDN with the viewer's `Range` header (key stays on the VM, costs egress). Hand-off links (`/api/play/external`) follow the same mode; the Stremio addon's `play` 302 goes to the CDN in `direct` mode and to `/stremio/{token}/file/{streamId}` (same pipe, bound to the device token) in `proxy` mode.
- Settings (Phase 6, `/settings?tab=profile|playback|subtitles|tv|sessions`): `PATCH /api/me/profile` (display name + one of the 8 avatar swatches), `POST /api/me/password` (`400 PW_WRONG | WEAK_PASSWORD`; clears `must_change_password` and deletes every other session of the user), `GET/POST/DELETE /api/me/device-token` (Stremio link: show / rotate / revoke), `GET/DELETE /api/me/sessions`. A member who got a temp password from the admin is pinned server-side to `/settings?tab=profile` (every other page redirects there, every other API answers `403 PASSWORD_CHANGE_REQUIRED`) until it is changed; temp passwords expire 48 h after they were issued (`401 AUTH_TEMP_EXPIRED` at login).
- Admin (Phase 6, `/admin`, `/admin/users`, `/admin/queue`, `/admin/activity`; members get the 403 box): `GET /api/admin/stats` (KPIs, 30-day bars, "Đang xem lúc này" from `views` beats ≤ 90 s), `GET/PATCH /api/admin/users` (`lock` = the member's active cloud jobs cancelled, then disabled + every session deleted + live stream handles dropped in one go, `unlock`, `role`, `revoke-stremio`, `resend` = a fresh temp password + the login link for a member who never logged in — `409 ALREADY_ACTIVE` otherwise), `POST /api/admin/users/[id]/reset-password` (`Gk7-mPx2-Q9w` temp code, must change at next login, valid 48 h), `DELETE /api/admin/users/[id] {confirm: username}` (jobs cancelled first, then one transaction: invites re-parented to the acting admin + FK cascade), `DELETE|POST /api/admin/invites/[id]` (revoke / recreate — `409 STILL_VALID` while the old link still works; the raw invite token is kept only while the invite is valid so the table can show + copy it), `GET/PATCH /api/admin/queue` (`prioritize` = app-side queue only; TorBox has no priority API, so the button appears only on app-queued rows), `GET /api/admin/activity[.csv]?kind=&userId=&month=` (CSV cells that start with `= + - @` are apostrophe-prefixed). Self lock / delete / demote and removing the last admin answer `409 SELF | LAST_ADMIN`. "Yêu cầu thêm phim" now also writes a `title_request` notification for every admin.
- Stremio addon (Phase 6, Android TV): `GET /stremio/{deviceToken}/manifest.json` + `catalog/{type}/{id}[/skip=N].json` (trending movie / series, anime, my-list — the same TMDB rows as the web home, Vietnamese) + `meta/…` (series list every episode) + `stream/…` (Phase 3 sources for the viewer's prefs: top 5 cached → `url` = our `play` 302 with the viewer's `quality` resolution first — a 4K viewer gets 2160p rows before 1080p since the TV plays MKV/HEVC natively —, 3 uncached → `infoHash`; also answers `tt…` ids through TMDB `/find` so the hand-off deep link works) + `subtitles/…` (Phase 5 rows served through `subs/{id}.vtt`) + `play?key=&hash=` (302; logs a `views` row `mode:'stremio'` + an activity line). Device tokens are revocable in Settings (and by the admin); unknown / revoked tokens → 404 JSON; every token is rate-limited (60 requests / min, `play` 10 / min; the proxy `file` pipe is exempt) → 429; malformed catalog paths → 400. URLs are always built on `APP_URL`. CORS `*` on `/stremio/*`. Dev: scenario `play-sample` makes the stream handler answer the local sample only.
- Ops (Phase 6): `GET /api/health` → `{ok}` for anonymous callers (Docker healthcheck), `{ok, db, version, torbox, sweeper}` for an admin session (503 when SQLite does not answer); SIGTERM / SIGINT fold the WAL into `lumen.sqlite` (`wal_checkpoint(TRUNCATE)`) so a stopped container leaves one complete file; nightly SQLite snapshot (`DATA_DIR/backups/lumen-YYYYMMDD.sqlite`, checkpointed first, mode 600, 14 kept, 03:15) and the daily "Tập mới" check (`my_list` series × TMDB `last_episode_to_air` ≤ 7 days → `new_episode` notification) run with the sweeper (`LUMEN_SWEEPER=1`); `public/robots.txt` disallows everything, every response carries `X-Robots-Tag: noindex, nofollow` + `nosniff` / `DENY` / referrer / permissions headers (Caddy adds HSTS); `public/manifest.webmanifest` + `/icons/*` make "Thêm vào màn hình chính" on iPhone a standalone app (`npm run icons` regenerates the PNGs).
- "Lần trước" (remembered release): an explicit row pick in the picker (▶ Phát / ▶ Thử phát / 📺 Mở bằng app / ⬇ Tải lên cloud) is stored per viewer × TITLE in `release_prefs` (`POST /api/sources/prefs {mediaKey, hash}`, `DELETE /api/sources/prefs?mediaKey=`; an episode key folds to `tv:<id>`). `GET /api/sources` answers `preferredHash` + `preferredApplies`; every primary path (hero ▶ / ▶ Tiếp tục, series primary, episode row, continue card, `?play=1`, resolve `auto` / `pickReason:'primary'`, Stremio stream order "⭐ Lần trước") uses that release while it is still cached and in the current list — series fall back to a cached row of the same release group + quality, then the same quality; an uncached pref never starts a download (the hero uses the best row and shows "Bản đã chọn không còn sẵn, dùng bản đề xuất"). The picker tags the row "Lần trước", focuses it first, and the footer link "Quên lựa chọn" deletes the pref. Logic: `src/lib/sources/release-pref-select.ts` (pure) + `release-prefs-store.ts`.
- `npm run db:generate` after editing `src/lib/db/schema*.ts` (writes `drizzle/`); migrations apply automatically on first DB open.
- `LUMEN_SWEEPER=0` disables the background `title_sources` sweeper (dev / QA runs that must not call TorBox behind the scripts; `GET /api/health` reports `sweeper`).
- `LUMEN_SCENARIOS=1` (dev only) enables `/dev/ui?state=…`, `POST /api/dev/scenario {flags[]}` (cookie `lumen_scenario`; a flag may carry a parameter: `cloud-sim=downloading:60:20`) and `POST /api/dev/seed` fixtures (seed additionally requires an admin session).
- Sources (Phase 3): `TORBOX_API_KEY` + `TORRENTIO_BASE` in `.env.local`; one server-side poller (5 s) tracks cloud jobs, a sweeper refreshes `title_sources` for hero / Top 10 / trending titles at boot (+10 s) and every 6 h. The TorBox CDN URL returned by `requestdl` embeds the API key: it only ever lives in the in-memory stream registry (`/api/play/resolve` answers an opaque `streamId`).
- `TRUST_PROXY=1` only behind Caddy (docker-compose sets it): otherwise `x-forwarded-for` is ignored and the login rate limit uses one shared bucket.
- Sessions expire server-side after 30 days (remember me) or 24 h (browser session) without activity; expired rows are pruned at boot and on every login.

## Known non-blocking choices

- A member opening `/admin/*` gets the 403 box inside the normal shell with HTTP **200**: the guard lives in the `(app)/admin` layout, and App Router layouts cannot change the status code (Next's `forbidden()` is still experimental). The JSON API answers a real 403.
- `/dev/ui` highlights no nav item (the mock hard-codes "Trang chủ"); the header derives the active item from the pathname.
- Toast stack keeps max 3 visible (spec) even though the mock demo shows 4.
- Device (Stremio) tokens are stored in plaintext on purpose so Settings can re-display the manifest URL; DB access = token access, same as a session row.

## Deploy (Azure VM, Docker + Caddy)

`docker-compose.yml` = `data-init` (makes the bind-mounted `./data` 1000:1000 mode 700) + `app` (this image, runs as the image's `node` user = uid 1000, `/data` bind mount, healthcheck, `LUMEN_SCENARIOS=0`, `TRUST_PROXY=1`, `STREAM_MODE` from `.env`) + `caddy` (automatic HTTPS for `APP_DOMAIN`, HSTS / noindex / nosniff headers, `admin off`, 10 MB request bodies, access log with tokens + query strings redacted, no buffering on the video pipes). `.env.example` is tracked and lists every key; `infra/deploy.sh` refuses to run while `APP_URL` / `APP_DOMAIN` / `ACME_EMAIL` / `SESSION_SECRET` / `ADMIN_*` are empty. `infra/azure/create-vm.sh` creates the resource group + static IP + NSG (22 from your IP only — `--ssh-source`, 80/443 public) + Ubuntu 24.04 B1ms VM with `infra/azure/cloud-init.yaml` (Docker, ufw, fail2ban, 2 GB swap, deploy user, data dir owned by uid 1000); `infra/deploy.sh` rsyncs the repo, copies `.env` (600), fixes the data dir ownership, backs the database up (default; `--no-backup`), builds on the VM, runs the SQLite migration in a one-off container (`infra/migrate.cjs`) before the running app is replaced, `docker compose up -d`, waits for the health check, curls `https://APP_DOMAIN/api/health` and prints the rollback recipe; `infra/backup.sh` is the nightly cron (WAL checkpoint + SQLite `.backup` + subs/jobs tarball, mode 600, newest 14 kept — restore = stop app → remove `-wal`/`-shm` → copy → start). The owner's step-by-step runbook (Vietnamese: domain → DNS → VM → `.env` → deploy → first invite → Android TV Stremio → key rotation → budget alert) is `infra/README-deploy-vi.md`. Local check without a domain: `APP_DOMAIN=localhost docker compose up` (Caddy uses its internal CA → `curl -k https://localhost/api/health`).
